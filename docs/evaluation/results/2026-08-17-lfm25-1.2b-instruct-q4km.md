# LFM2.5-1.2B-Instruct Q4_K_M cleanup evaluation

- Date: 2026-08-17
- Device: Google Pixel 7
- Runtime: Liquid LEAP 0.10.9
- Corpus: 24 direct-text cases; no microphone or STT input
- Primary raw result: [2026-08-17-lfm25-1.2b-instruct-q4km.jsonl](2026-08-17-lfm25-1.2b-instruct-q4km.jsonl)
- Focused D/E result: [2026-08-17-lfm25-1.2b-instruct-q4km-prompts-de.jsonl](2026-08-17-lfm25-1.2b-instruct-q4km-prompts-de.jsonl)

## Outcome

**No-go for automatic cleanup.** The 1.2B model is much more capable than 230M and 350M, but no
prompt met the zero-meaning-change requirement. The best exact score was 13/24, while that prompt
also summarized inputs, answered a dictated command, dropped technical details, and failed all
three explicit self-corrections. The most conservative prompt preserved 98.4% of scored anchors
after fallbacks but mostly copied disfluencies and still failed every self-correction.

## A/B/C matrix

| Prompt | Exact | Anchor preservation | Fallbacks | Median TTFT | Median total |
|---|---:|---:|---:|---:|---:|
| Baseline rules | 4/24 | 73.8% | 3/24 | 2,635 ms | 3,426 ms |
| Command envelope | 6/24 | 98.4% | 3/24 | 2,091 ms | 2,807 ms |
| Isolated rules | 13/24 | 82.0% | 2/24 | 3,149 ms | 3,801 ms |

The full 72-run matrix took 240,634 ms. The isolated prompt's higher exact score hid unsafe
behavior: it summarized agreement and ordered instructions, dropped SDK values, answered the haiku
command, weakened uncertainty wording, and did not resolve Tuesday → Thursday, Sarah → James, or
three → four-thirty corrections.

The command envelope's preservation score is not a cleanup pass. It often copied the raw text,
omitted punctuation/capitalization, leaked prompt scaffold text, and relied on fallbacks for command
answers.

## Focused D/E prompt iteration

| Prompt | Exact | Anchor preservation | Fallbacks | Median TTFT | Median total |
|---|---:|---:|---:|---:|---:|
| Strict minimal edit | 0/24 | 78.7% | 1/24 | 4,182 ms | 4,889 ms |
| Few-shot corrections | 8/24 | 80.3% | 3/24 | 6,112 ms | 6,956 ms |

The 48-run D/E matrix took 304,337 ms. The strict prompt paraphrased, answered commands, converted
numbers to words, and never exactly matched. The few-shot prompt sometimes copied a demonstration
instead of the current input and produced a 10.2-second outlier. Both are rejected.

## Safety follow-up

After the raw model comparison, the app's conservative guard added lexical/intent checks for
meta-summaries, assistant answers, novel words, negation, uncertainty, names/case, numbers,
acronyms, technical tokens, and explicit corrections. It also strips leaked prompt suffixes. These
checks make rejected output fall back to raw text; they do not turn the model into a successful
cleanup engine, and the recorded JSONL remains the unaltered on-device evaluation evidence.

## Decision

Reject all tested generic LFM2.5 candidates for automatic cleanup. Preserve 230M as the latency
baseline and 1.2B as the capability baseline. Do not join cleanup to STT. Move next to an independent
STT evaluation, and revisit cleanup later with a task-specific fine-tune or a stronger model only if
its memory/latency budget is acceptable.
